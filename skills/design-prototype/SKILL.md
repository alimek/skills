# Design prototype

The user decides a design by looking at it. Everything you draw stays **WIP** until the user accepts one variant; only then does it become part of the design file's real pages. Load the Figma skills its tools require before calling them.

## Steps

1. **Ground.** Open the Figma file and the screens the task points at, and read the existing components, tokens and the breakpoints those screens already cover. Done when you can name the target page and the components you will reuse.
2. **Draw variants.** Build the options on the file's WIP page, as frames labelled **A**, **B**, **C**, each made from the existing design-system components and covering every breakpoint the target screen has. Variants differ in one idea each, stated in a line under the label. Done when each variant is complete enough to judge on its own.
3. **Show.** Send a screenshot and a Figma link per variant, with its one-line idea, and ask the user to pick a letter or correct one. Apply corrections on the WIP page and show again. Done when the user explicitly accepts one variant.
4. **Promote.** Move the accepted variant to the page where that screen lives, replacing the frames it supersedes. Delete the rejected variants and any stale frames you created from the WIP page. Done when the WIP page holds nothing from this task and the real page shows only the current design.
5. **Record.** Return the final frames' Figma node links, their screenshots and the decisions the user made on the way, including the options they rejected and why. Done when a spec writer could describe the change without opening this conversation.
